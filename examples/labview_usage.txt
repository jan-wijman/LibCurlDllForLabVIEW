LabVIEW DLL Import Wizard settings
===============================

DLL Name: curl_lv.dll
Calling convention: C
Function names: Use exact names from the header.

Example import signatures for LabVIEW:

For opening a URL/auth reference:
Return type: I32
Parameters:
- url: C String
- headers: C String (default headers)
- username: C String
- password: C String
- bearer_token: C String
- reference: I32*

For closing a reference:
Return type: I32
Parameters:
- reference: I32

For converting an error code to text:
Return type: I32
Function: lv_curl_error_string
Parameters:
- error_code: I32
- error_string_buffer: C String
- error_string_buffer_size: I32
- actual_error_string_size: I32*

For getting common header templates:
Return type: I32
Parameters:
- headers_buffer: C String
- headers_buffer_size: I32
- actual_headers_size: I32*

For sync request functions:
Return type: I32
Parameters:
- method: I32
- reference: I32
- endpoint: C String
- headers: C String (optional request headers)
- body: C String
- response_buffer: C String
- response_buffer_size: I32
- actual_response_size: I32*
- http_status_code: I32*

For sync multipart POST:
Return type: I32
Function: lv_curl_post_multipart
Parameters:
- reference: I32
- endpoint: C String
- headers: C String (optional request headers)
- text_fields: C String (one name=value entry per line)
- file_fields: C String (one name=path entry per line)
- response_buffer: C String
- response_buffer_size: I32
- actual_response_size: I32*
- http_status_code: I32*

For async start functions:
- reference: I32
- endpoint: C String
- headers: C String (optional request headers)
- body: C String (POST only)
- request_id: I32*

For async polling:
- chunk_buffer: C String
- chunk_buffer_size: I32
- actual_chunk_size: I32*
- is_last_chunk: I32*

For diagnostics:
Return type: I32
Function: lv_curl_get_latest_errors_info
Parameters:
- errors_buffer: C String
- errors_buffer_size: I32
- actual_errors_size: I32*

Polling flow example
--------------------
1. Call `lv_curl_global_init()` once.
2. Call `lv_curl_open()` with base URL, default headers, username, password, and/or bearer token.
3. Call `lv_curl_async_get_start(reference, endpoint, optional_headers, ...)` or `lv_curl_async_post_start(reference, endpoint, optional_headers, ...)`.
4. Loop:
   a. Call `lv_curl_async_read_chunk()`.
   b. If return value is `LV_CURL_SUCCESS`, append the chunk to your LabVIEW string.
   c. If return value is `LV_CURL_ERROR_ASYNC_NO_CHUNK`, wait briefly and retry.
   d. If return value is `LV_CURL_ERROR_ASYNC_COMPLETE`, the request finished and all data has been received.
5. Optionally call `lv_curl_async_get_state()` to inspect the final state and HTTP status code.
6. Call `lv_curl_close(reference)`.
7. Call `lv_curl_global_cleanup()` when your application exits.

Asynchronous POST polling flow
------------------------------
1. Call `lv_curl_async_post_start(reference, endpoint, headers, body, request_id)`.
2. Use a JSON/text body for REST APIs, for example `{"model":"llama3.2","prompt":"Hello","stream":true}`.
3. Store the returned `request_id`.
4. Repeatedly call `lv_curl_async_read_chunk(request_id, chunk_buffer, chunk_buffer_size, actual_chunk_size, is_last_chunk)`.
5. If the return value is `LV_CURL_SUCCESS`, append exactly `actual_chunk_size` bytes from `chunk_buffer` to your response string or byte array.
6. If `is_last_chunk` is `1`, that chunk is the final chunk returned with data.
7. If the return value is `LV_CURL_ERROR_ASYNC_NO_CHUNK`, wait briefly and poll again.
8. If the return value is `LV_CURL_ERROR_ASYNC_COMPLETE`, no chunk was returned in that call and all queued data has already been read.
9. If the return value is `LV_CURL_ERROR_BUFFER_TOO_SMALL`, allocate a larger `chunk_buffer` and call `lv_curl_async_read_chunk()` again with the same `request_id`.
10. Optionally call `lv_curl_async_get_state(request_id, state, http_status_code)` after completion to read the final HTTP status code.
11. If any call returns an error code, call `lv_curl_get_latest_errors_info()` to read and flush the detailed diagnostics.

Buffer management
-----------------
- Allocate response, header-template, chunk, and diagnostic buffers large enough for expected strings.
- If a buffer is too small, `LV_CURL_ERROR_BUFFER_TOO_SMALL` is returned.
- The API returns actual output sizes through the matching `actual_*_size` parameter.
- Response and chunk buffers are binary-safe. Use `actual_response_size` or `actual_chunk_size` as the valid byte count.
- The DLL appends a trailing NUL to response/chunk data only when there is spare buffer capacity.
- For async chunks, a too-small buffer does not discard the chunk; allocate a larger buffer and retry.
- Detailed diagnostic text is queued internally. Call `lv_curl_get_latest_errors_info()` after a non-success return code to copy and flush it.
- `lv_curl_get_latest_errors_info()` does not flush the queue when the diagnostics buffer is too small, so you can allocate a larger buffer and retry.

Header formatting
-----------------
- Pass default headers to `lv_curl_open()` as a single string with one header per line.
- Pass optional request headers to sync calls and async start calls the same way.
- Pass an empty string when a specific request does not need extra headers.
- For `lv_curl_post_multipart()`, do not pass `Content-Type: multipart/form-data`; libcurl adds the boundary automatically.
- `lv_curl_get_header_templates()` returns common header templates as one string with one header per line.
- The templates are examples; replace placeholder values like `<token>` and `<key>` before using them.
- Example:
  "Accept: application/json\r\nUser-Agent: LabVIEW Wrapper\r\n"

Multipart POST formatting
-------------------------
- `text_fields` uses one `name=value` entry per line.
- `file_fields` uses one `name=path` entry per line.
- Either string may be empty, but at least one field is required.
- Example text fields:
  "description=Test upload\r\ncategory=logs\r\n"
- Example file fields:
  "file=C:\temp\report.txt\r\nimage=C:\temp\screenshot.png\r\n"

Endpoint formatting
-------------------
- Pass the base URL to `lv_curl_open()`, for example `"https://example.com:8443/api"`.
- Pass the endpoint to sync calls and async start calls, for example `"items"` or `"/items"`.
- Empty endpoint uses the base URL as-is.
- A full `http://` or `https://` endpoint overrides the base URL for that request.

Authentication
--------------
- For basic or negotiated libcurl authentication, pass username and password to `lv_curl_open()`.
- For bearer-token authentication, pass the token without the `Bearer ` prefix to `lv_curl_open()`.
- Pass empty strings for unused authentication fields.

Bitness
-------
- Build 64-bit DLL for 64-bit LabVIEW.
- Build 32-bit DLL for 32-bit LabVIEW.
